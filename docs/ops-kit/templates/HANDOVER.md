# HANDOVER.md — تسليم الجلسة

> **ثلاث جمل. لا أكثر.** هذا الملف يُكتب في نهاية كل جلسة، ويُقرأ في أول الجلسة التالية.
>
> **لا يُقبل «تم العمل».** يُقبل `typecheck exit 0 · 115/115 · commit c489a23`.
>
> السبب: 43 فرعًا من 118 في هذه المحفظة فيها شغل غير مدموج. أغلبه ضاع لأن أحدًا لم يكتب أين توقف.

---

## الجلسة: <YYYY-MM-DD> · <اسم/معرّف الوكيل>

**ما تغيّر فعلًا:**
```
<ملفات + commit SHA + اسم الفرع>
مثال: engines/transactions/src/payments-service.ts · commit c489a23 · فرع feat/nile-payments-engine (محلي، غير مدفوع)
```

**ما تحقّقت منه:**
```
<الأمر + الناتج>
مثال: npm test → Test Files 10 passed · Tests 115 passed | 2 todo · exit 0
```

**ما لم يكتمل:**
```
<الشيء المحدد + سببه + ما الذي يحتاجه>
مثال: اختبار التزامن بجلسَتين — PGlite باتصال واحد لا يكفي — يحتاج PostgreSQL حقيقي عبر NILE_TEST_PG_ADMIN_URL
```

## قواعد التسليم

| ممنوع | البديل |
|---|---|
| «تم بنجاح» | `exit 0` + الأعداد |
| «الاختبارات تعمل» | `115/115` |
| «تم النشر» | `git ls-remote` + الـSHA |
| «لا يوجد X» | الأمر الذي أثبت عدم وجوده |
| ترك الشغل على فرع | دمج، أو PR، أو قول صريح بأنه محلي |

## قبل أن تُغلق

- [ ] الشغل مدفوع أو مدموج، أو مكتوب صراحةً أنه محلي
- [ ] `EVIDENCE.md` فيه سطر لكل ادعاء جديد
- [ ] `STATUS.md` محدَّث إن تغيّرت الحالة
- [ ] أي قرار جديد مُرقّم ببادئة المنتج في `DECISIONS.md`
- [ ] لا أسرار في الملفات ولا في الشات
