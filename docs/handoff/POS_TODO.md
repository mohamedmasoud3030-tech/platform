## المرحلة 1 — محرك المدفوعات (المهمة 3 في `STATUS.md`)

> **العقد الكامل:** `docs/architecture/proposals/0007-payment-engine.md` — **اقرأه كله قبل كتابة أي سطر.**
> **الشرط:** فرع جديد من `main` **بعد** دمج `PR #4`. **الاختبارات أولًا** (`test-driven-development`).

### 1.1 النموذج البياني — هجرة `0003_payments`

- [ ] جدول الورديات (shifts): فتح، إغلاق، مبلغ متوقع مقابل معدود
- [ ] جدول المدفوعات: 4 طرق (نقدًا، بطاقة، محفظة إلكترونية، تحويل بنكي)
  ⚠️ الطرق غير النقدية **بمرجع خارجي فقط — بلا تكامل بوابة دفع**
- [ ] تقسيم الدفع (split tender) + الباقي (change)
- [ ] المرتجعات: كاملة وجزئية
- [ ] **إصلاح `cash_movements`** — وضعه الحالي معطوب (الحقيقة F2):
  - فيه `shift_id NOT NULL` لكن **مافيش جدول ورديات ولا مفتاح أجنبي**
  - **مافيش رابط** لبيع أو دفعة
  - **مافيش مفتاح مستأجر مركّب** (composite tenant key)
  - عمود `status` مصمم ليتغير من `pending` إلى `posted` — **وهذا مستحيل بعد `PR #4`** لأنه يسحب صلاحية UPDATE

### 1.2 ⚠️ قيود تقنية إلزامية (من الحقائق F4 و F5)

- [ ] **الجداول append-only فقط** — `nile_app` لا يملك UPDATE/DELETE بعد `PR #4`
  ⇒ التحول `pending → posted` **لا يُنفَّذ بالتحديث**، بل بإدراج صف جديد
- [ ] **ممنوع استخدام `SELECT … FOR UPDATE / FOR SHARE`** على الجداول المقفولة
  ⇒ PostgreSQL requires UPDATE privilege for row locks، و`nile_app` فقدها (مُتحقَّق على PostgreSQL 18.4)
  ⇒ **البديل: advisory locks**
- [ ] كل جدول جديد **لازم ملف هجرته يعمل REVOKE للـ UPDATE/DELETE**
  (الامتيازات الافتراضية في `0001_security_hardening.sql` تمنحها تلقائيًا — الثغرة P4-4)

### 1.3 اختبارات القبول — **الثمانية كلها إجبارية** (من §6)

- [ ] **1. الصلاحيات:** UPDATE وDELETE يفشلان كـ`nile_app` على كل جدول جديد وعلى `cash_movements`
- [ ] **2. RLS والمفاتيح المركّبة:** لا يمكن قراءة أو الإشارة لبيع/دفعة/وردية مستأجر آخر
- [ ] **3. Idempotency:** إعادة الإرسال تُرجع نفس النتيجة؛ نفس المفتاح بمحتوى مختلف ⇒ **409**
- [ ] **4. الأموال:** تقسيم دفع مع الباقي على حالات مولَّدة؛ رفض السالب والصفر **من قاعدة البيانات نفسها**
- [ ] **5. التزامن على PostgreSQL حقيقي** (‏PGlite لا يصلح — اتصال واحد فقط):
  - مرتجعان متسابقان على نفس الدفعة **لا يتجاوزانها أبدًا**
  - استدعاءا `openShift` على نفس الصندوق ⇒ **وردية مفتوحة واحدة فقط**
- [ ] **6. الدرج:** الحالات الذهبية لـ kayyal تظل ناجحة؛ النقد المعلّق يظهر في `expectedInDrawer` **ولا يظهر في `expectedPosted`**
- [ ] **7. إغلاق الوردية:** الفرق = المعدود − المتوقع، والإغلاق مرتين idempotent
- [ ] **8. فحص الطفرة (mutation):** إزالة REVOKE أو CHECK أو advisory lock **لازم تكسّر اختبارًا**

### 1.4 قواعد أموال لا تُمس

- [ ] **`engines/transactions/test/golden.test.ts` ممنوع تغييره بدون ADR** (`docs/REUSE.md`)
